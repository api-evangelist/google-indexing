# Google Indexing API

> The Google Indexing API (v3) lets a site owner tell Google directly when a page has been added,
> updated, or removed, instead of waiting for a crawl. It is a two-operation API. Google restricts its
> use to pages carrying JobPosting structured data, or BroadcastEvent embedded in a VideoObject. It is
> free of charge, gated on Search Console ownership verification, and capped at 200 publish requests per
> day per Google Cloud project by default.

Generated by API Evangelist on 2026-08-13. Google does not publish an llms.txt
(https://developers.google.com/llms.txt returned HTTP 404 on 2026-08-13), so this file is generated from

## What you can actually do

- Submit a URL for crawling: `POST https://indexing.googleapis.com/v3/urlNotifications:publish` with
  `{"url": "...", "type": "URL_UPDATED"}`.
- Tell Google a page is gone: same endpoint with `"type": "URL_DELETED"`.
- Check what Google last heard from you about a URL:
  `GET https://indexing.googleapis.com/v3/urlNotifications/metadata?url=...`. This only works for URLs
  previously accepted from the same project.

There is nothing else. No listing, no search, no status polling, no webhooks, no events.

## Before your first call

All four steps are required; skipping any of them produces a 401 or a 403.

1. Create a Google Cloud project and enable the Indexing API.
2. Create a service account and download its JSON private key.
3. Verify the site in Google Search Console.
4. Add the service account email as a delegated site owner on that Search Console property.

Auth is OAuth 2.0 with the scope `https://www.googleapis.com/auth/indexing`, presented as
`Authorization: Bearer <token>`. The service account mints tokens via a signed JWT assertion at
`https://oauth2.googleapis.com/token`.

## Limits you need to plan around

- 200 publish requests per day per project (URL_UPDATED and URL_DELETED combined). Resets midnight
  Pacific.
- 180 getMetadata requests per minute per project.
- 380 requests per minute per project across all endpoints.
- Up to 100 requests can be combined in one batch.
- **No rate-limit headers.** The API returns no `RateLimit-*`, `X-RateLimit-*` or `Retry-After` header.
  Remaining quota is only visible in the Google API Console. Budget locally; you cannot read it back.
- Exhaustion shows up as `403 dailyLimitExceeded` / `403 quotaExceeded` or `429 rateLimitExceeded`.

## Errors

Errors use the Google `google.rpc.Status` envelope, **not** RFC 9457 problem+json:

```json
{"error":{"code":401,"message":"...","status":"UNAUTHENTICATED",
 "details":[{"@type":"type.googleapis.com/google.rpc.ErrorInfo","reason":"CREDENTIALS_MISSING",
 "domain":"googleapis.com"}]}}
```

The one you will hit most: `403 Permission denied. Failed to verify the URL ownership.` That means step
3 or 4 above is incomplete, not that your token is bad.

## APIs

- [urlNotifications:publish](https://developers.google.com/search/apis/indexing-api/v3/using-api): submit
  or remove a URL. Base `https://indexing.googleapis.com/v3`.
- [urlNotifications/metadata](https://developers.google.com/search/apis/indexing-api/v3/using-api): read
  the latest notification state for a URL.

events, no AsyncAPI, no GraphQL, no published .proto, no CLI, no sandbox or test mode, no idempotency
key, no pagination, no rate-limit headers, no SLA, no roadmap, and no deprecation policy.
